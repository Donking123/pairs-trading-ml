## C. New `datastream/run_engine_backtest.py` (full-pipeline orchestrator)

Distinct from `run_backtest.py`. It:

1. Optionally fetches WRDS data + screens if parquet is missing (`--fetch`).
2. Auto-detects the backtest date range from the ADR price parquet.
3. Overrides `approved_date`/`expiry_date` so the whole window is tradeable
   (reproduction-backtest mode).
4. Runs the **production `BacktestEngine` from `src/asian_adr/`** (not the inline
   single-file logic) and prints the paper benchmark-validation table.

This is the "reproduce the paper" entry point; `run_backtest.py` is the
standalone inline engine.

## E. Session fixes (2026-06-07)

### E1. Survivorship-bias warning — `datastream/run_asian_adr_screening.py`

**Error found:** The PIT filter fallback (when `startdate`/`enddate` columns are
absent from the reference table) silently logged at `DEBUG` level — invisible in
normal runs. A user passing the wrong reference file would get survivorship-biased
results with no indication.

**Fix:** Elevated to `WARNING` with an actionable message:
> "adr_reference has no startdate/enddate columns — survivorship bias NOT corrected.
>  Run fetch_pit_adr_reference.py and pass adr_reference_pit.parquet via
>  --adr-reference to fix this."

---

### E2. Reference table missing delisted ADRs + name-period duplicates — `datastream/fetch_datastream_adr_data.py`

**Errors found (three, related):**

| # | Error | Impact |
|---|-------|--------|
| E2a | `ADR_REFERENCE_SQL` had no `startdate`/`enddate` columns — reference was a static snapshot of currently-active pairs only. Delisted pairs were silently absent from the candidate universe. | Survivorship bias in pair selection: losing trades on delisted pairs were never attempted. |
| E2b | Adding `startdate`/`enddate` revealed that `wrds_ds_names` stores one row **per name period** (new row on each ticker/name change). The cross-join `ADR periods × underlying periods` produced up to 36 rows per economic pair (11,188 rows for 1,834 unique pairs). | Reference had duplicate pairs with inconsistent/invalid date windows; downstream `drop_duplicates` kept an arbitrary row. |
| E2c | 225 pairs had `startdate > enddate` after the pair-level intersection — artefacts of non-overlapping name periods between the two legs. | PIT filter would have incorrectly admitted or excluded these pairs. |

**Fixes applied:**

1. **Added `startdate`/`enddate` to `ADR_REFERENCE_SQL`** — fetches `a.startdate`,
   `a.enddate`, `u.startdate`, `u.enddate` from `wrds_ds_names` for both legs.
   Both active and delisted pairs are now included.

2. **Sentinel date conversion** — WRDS uses `2079-06-05` to represent "still active"
   instead of NULL. Converted to `NaT` before aggregating so open-ended records
   are handled correctly in `min`/`max` aggregations.

3. **Name-period deduplication** — grouped by
   `(adr_ticker, adr_isin, adr_infocode, underlying_ticker, underlying_exchange,
   underlying_currency)` and aggregated:
   - `adr_startdate = MIN(adr_startdate)` — earliest start across all name periods
   - `adr_enddate = MAX(adr_enddate)` — NaT if any period is open-ended, else latest end
   - Same for `underlying_startdate` / `underlying_enddate`
   - `adr_ratio = FIRST` (unchanged across name periods)

4. **Pair-level date computation** — after deduplication:
   - `startdate = MAX(adr_startdate, underlying_startdate, skipna=False)` — unknown
     start propagates NaT (survivorship-safe)
   - `enddate = MIN(adr_enddate, underlying_enddate)` — pair dies when first leg ends

5. **Invalid window filter** — pairs where `startdate > enddate` are dropped with a
   `WARNING` log. 225 such pairs were dropped in the first clean run.

**Net effect:** Reference shrank from 11,188 rows → 7,794 clean, deduplicated pairs
with correct PIT date windows. The PIT filter in `run_asian_adr_screening.py` now
activates automatically for all runs — `fetch_pit_adr_reference.py` is redundant
for new runs (existing `adr_reference_pit.parquet` files remain valid).

Seven additions (3 enhancements to existing scripts, 3 new scripts) to probe

### Enhancements to existing scripts

| Script | Addition | What it catches |
|--------|----------|-----------------|

## H. Strategy correctness fixes — Issues 2, 3, 4 (2026-06-08)

Three issues identified in the strategy-correctness review of `datastream/`. All
three produce results that are more optimistic than reality, so applying them
will lower headline RUCE-net numbers.

### H1. Unadjusted prices (Issue 2)

**Error:** `cumadjfactor` was fetched from `wrds_ds2dsf` and stored in the
parquet files but never applied. Dividend ex-dates and stock splits created
sudden discontinuities in both the ADR and local price series, causing the
spread to spike or collapse artificially. Those spikes triggered false trade
entries and (more importantly) biased the pair-selection cointegration tests.

**Fix applied to three files:**

| File | Function changed | What changed |
|------|-----------------|--------------|
| `datastream/run_backtest.py` | new `_adj_prices()` + `load_panel()` | `adj = raw / cumadjfactor` applied to both ADR and local `close` (and local `open`) before the spread column is built |
| `datastream/run_asian_adr_screening.py` | new `_adj_prices()` + `reconstruct_spread()`, `_estimate_ratio_from_prices()`, `_bulk_estimate_ratios()`, `screen_pair()` | Same adjustment in screening; `screen_pair()` now includes `adj_factor` in the column slices it passes downstream |
| `research/run_walkforward.py` | `_build_panel()` | Mirrors `load_panel()` — uses `_bt._adj_prices()` on both legs |

**Convention:** In WRDS Datastream `wrds_ds2dsf`, `cumadjfactor` is a
backward-adjusted factor (> 1 for dates prior to splits/bonus issues). The
formula `adj = raw / cumadjfactor` normalises all historical prices to the
current share-count base without altering the most recent price. Falls back
to raw prices when the column is absent, zero, or NaN — so existing parquets
without `adj_factor` continue to work unchanged.

---

### H2. Local leg filled at next-day close instead of open (Issue 3)

**Error:** `backtest_pair()` used `local_close_usd[j]` (next-day **close**)
for the local leg entry fill. The paper specifies Asia-**open** fill — the
trade is entered at the open of D+1, not at the close. Using the close
overstates execution quality (the spread has already partially converged
by close, making the entry look better than it is).

**Fix:**

- `load_panel()` now computes `local_open_usd = adj_open × fx_mid` and joins
  it into every pair's DataFrame when the `open` column is available in the
  parquet (it always is — `GLOBAL_PRICES_SQL` has fetched `open` from the
  start).
- `backtest_pair()` extracts the `local_open_usd` array; at D+1 entry it
  uses `local_open_usd[j]` as the fill price. A NaN-safe fallback to
  `local_close_usd[j]` is included for any day where `open` is missing.
- `_build_panel()` in `run_walkforward.py` mirrors this change.

**Net effect:** Entry prices are slightly worse (open is typically closer to
the prior close before intraday convergence). Expect a modest reduction in
median RUCE-net on re-run.

---

### H3. Holiday gaps silently accepted as "overnight" (Issue 4)

**Error:** The inner-join calendar (`how="inner"` over ADR + local + FX) means
"next bar" (`j = i + 1`) can span 2–4 calendar days during Asian holiday
periods. No warning was emitted. A gap of 4 days violates the overnight-timing
thesis: the ADR short is held unhedged for multiple days, and the convergence
signal may have fully reverted before the local leg is entered.

**Fix:**

- `backtest_pair()` now checks `(dates[j] - dates[i]).days > max_overnight_gap_days`
  immediately after determining `j = i + 1`.
- If the gap exceeds the threshold the entry is **skipped** (state reset to
  FLAT) and a `log.debug` message is emitted with the pair ID and gap length.
- Default threshold: **4 calendar days** (allows the normal Fri-US-close →
  Mon-Asia-open 3-day gap; flags multi-holiday stretches of 5+ days).
- New CLI flag `--max-overnight-gap` (default 4) on both `run_backtest.py` and
  `run_walkforward.py` so the threshold is adjustable without editing code.
  Wired into the `cfg` dict and forwarded through `run_fold()`.

**Interpretation of the changes:**

- **−0.51pp RUCE-net** is the combined effect of H1–H3. The open-fill correction
  (H2) is the primary driver: entering at the local open rather than the local
  close is a slightly worse fill as the spread has partially converged by close.
  The gap filter (H3) removes entries where the overnight assumption was already
  violated, accounting for most of the −505 fewer attempts.

  (5.28%) is the number to cite going forward.

  elevated post-COVID spread dispersion in the 2023 test window.
- The roll cost median dropped slightly (1.93% → 1.87%) because the gap-filter
  removes some high-spread (and thus higher-roll-cost) entries around holiday
  periods.
